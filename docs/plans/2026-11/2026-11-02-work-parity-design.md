# run.py: pulling useful features from the work dotfiles — design

**Date:** 2026-11-02 **Status:** approved

## Goal

Review `~/dotfiles/run.py` (the work repo, 4.7k lines) against this repo's `run.py` (2.4k lines, already at
infrastructure parity after PR #38) and port the command-level features that are useful here. The review found the
framework layer (`Command`, `get_commands`, `style`/`printf`, `shell_command`, parser, vault, `clean`, `makefile`)
already matches or exceeds work's; this design covers what is left.

## Decisions

| Question                           | Decision                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Scope                              | Review items 1-5 and 7, plus `install-uv`, `install-hatch`, `diagnose`, the uv/venv machinery, and `lock*`     |
| Skipped from the review            | Item 6 (`uv-tools-dump`, `vscode-extensions-dump`): the manifests are layered and work's fixer hook is wrong   |
| `uv-public.sh` integration         | **Wrap the script.** Helpers take `public: bool = True` and use the script as the uv executable                |
| Default for `public`               | `True` for every project-scoped uv call (existing repo policy: all uv calls go through `uv-public.sh`)         |
| Delivery                           | Two stacked PRs, each in its own worktree; B branches from A                                                   |
| `status` vs `doctor`               | `status` is a fast read-only subset built from the same `check_*` functions `doctor` runs                      |
| Work scripts                       | Copied with a scrub pass (see PR B); `loadenv.py` is not copied (nothing uses it)                              |
| Dead helpers in work's `run.py`    | Not ported: `uv_pip_list`, `uv_tree`, `import_script_module`, `ensure_dependencies_installed`, `install_homebrew`, `typestyle`, `dim_paren`, `optstyle`, `format_elapsed`, `canonical_pkg_name` |

## PR A: hooks, doctor, Claude tracking, small items

Plan: [`2026-11-02-work-parity-a-plan.md`](2026-11-02-work-parity-a-plan.md).

### `run-hooks`, `pre`, `prepare-hooks` (Codebase group)

- `RunHooksCommand` wraps `prek run` with the full option set: positional `HOOK|PROJECT...`, `-a/--all-files`,
  `--files`, `-d/--directory`, `-s/--from-ref`, `-o/--to-ref`, `--last-commit`, `--skip` (repeatable), `--stage`,
  `--show-diff-on-failure`, `--fail-fast`, `--dry-run`, `-v/--verbose`. Output streams straight to the terminal and the
  command exits with prek's return code.
- The hook filter is placed **before** the options in the generated argv. prek's `--files` is greedy, so work's
  hooks-last ordering would swallow a trailing hook name as a file.
- `PreCommand` becomes a subclass of `RunHooksCommand` (no file-selection options, `all_files` forced on). Its
  description is unchanged so the `Makefile` line is unchanged. It now propagates prek's exit code (it previously
  ignored it).
- `PrepareHooksCommand` wraps `prek prepare-hooks`. `install-hooks` and `uninstall-hooks` are untouched. All three call
  bare `prek`, as `pre` does today.

### `doctor`

- New check `hooks`: for every type in `GIT_HOOK_TYPES` (mirrors `default_install_hook_types`; a test pins them), the
  shim must exist and contain prek's `generated by prek` marker. The hooks directory comes from
  `git rev-parse --git-path hooks`, which is correct in linked worktrees and with `core.hooksPath` (work's version
  hard-codes `.git/hooks/pre-commit`). Fix: `prek install`. This matters because no bootstrap stage installs hooks and
  `pre-push` is the public-repo leak guard.
- New check `brewfile`: `brew bundle check` once per layer Brewfile (layers from the same `dotfiles_layers` probe
  `check_layers` uses), run through `env HOMEBREW_NO_AUTO_UPDATE=1`. Fix: `brew bundle --file` for each unsatisfied
  Brewfile. Runs last (slowest).
- `confirm(prompt, *, default=True, indent=0)` helper. EOF declines; Ctrl-C propagates to `main()` (exit 3) rather than
  being read as "no".
- `doctor --fix` now asks before each fix; `-y/--yes` skips the prompts and implies `--fix`. This is a deliberate
  behavior change: the `links` fix moves files out of `$HOME`.
- `bootstrap --verify` runs `doctor`, so it inherits both checks.

### `track-claude` (Dotfiles group)

Ingests real files under `~/.claude/{agents,commands,skills,hooks,rules}` into `stow/claude/.claude` and restows with
`bash stow.sh claude`. `rules` is added to work's four subdirs (hand-authored, and already tracked here); `plugins`,
`scripts`, and `statusline` stay excluded. `stow.sh` always uses `--no-folding`, so "regular file" reliably means
"untracked". A tracked subdir that is itself a symlink is skipped (ingesting would move repo files onto themselves).
Flow: list files, flag conflicts (destination exists), `--dry-run` stops, `confirm()`, move, restow, print the commit
hint.

### `NO_COLOR` and PEP 723

- `NO_COLOR: bool = bool(os.getenv('NO_COLOR'))` (no-color.org: any non-empty value) makes `style()` return plain text.
  Work tests `== 'true'`, which deviates from the convention.
- `run.py` gains a PEP 723 `# /// script` block (`requires-python = ">=3.9"`, `dependencies = ["PyYaml >= 6.0"]`),
  closing the TODO at `run.py:98`. A test pins the block to `pyproject.toml`. `list-hosts` stops conflating a missing
  `yaml` module with an unparsable inventory.

## PR B: installers, diagnose, uv/venv machinery, lock commands

Planned in detail after PR A merges (it builds on A's doctor refactor).

### Scripts

`install_uv.py` and `install_hatch.py` (`scripts/install/`), `python_diagnostic.py` and `venvshell.py`
(`scripts/env/`) are copied from the work repo. Scrub rules, applied identically to all four and recorded in each
directory's README so a re-sync is repeatable:

- Header: keep the author name; drop the email, the "Source" and "Updated in" provenance lines that name the internal
  tool, and its version.
- Remove the one internal bug-tracker link comment in `install_uv.py` (keep the explanation of the workaround).
- Reword the employer-specific phrasing in the CA/host explanations (docstrings about native trust stores) to
  "corporate CAs/hosts".
- Verify with the leak guard and a `--help` smoke test per script.

### Commands

`install-uv`, `install-hatch` (a shared `_InstallToolCommand` base, `register=False`), `diagnose`, `install`, `dev`,
`shell`, `status`, `clean --no-envs`, `lock`, `lock-check`, `lock-upgrade`. `install` has no `--all` (no extras are
defined in `pyproject.toml`). Root options gain `--uv-verbose` / `DOTFILES_UV_VERBOSE` (sets `RUST_LOG=uv=debug`); the
PR #38 design omitted it because nothing was uv-driven.

### uv helpers and `uv-public.sh`

- `uv_command(*args, public=True) -> list[str]` builds the argv. `public=True` uses `UV_PUBLIC` as the executable, which
  is exactly what `run.py` already does at four call sites; those move onto the helper with identical argv, so their
  tests do not change. `public=False` is for tool-level calls (`uv --version`, `uv tool ...`).
- The script stays the single source of truth for env neutralization (no duplicated `UV_*` list in Python). When `uv`
  was found by `find_uv_executable()` outside `PATH` (for example right after `install-uv`, before the shell restarts),
  the helper prepends its directory to `PATH` for the call so the script's `exec uv` still resolves.
- Ported with work's signatures: `find_uv_executable`, `check_uv`, `ensure_uv`, `run_installer`, `uv_run`, `uv_sync`,
  `check_python`, `check_script_validity`, `parse_pyvenv_version`, `count_venv_packages`, `get_external_active_venv`,
  `is_venv_stale`, `validate_venv`, `ensure_venv`, `enter_venv`; new: `uv_lock`.

### Lock commands

- `lock [--refresh]`: `uv lock`.
- `lock-check`: `uv lock --check`; exits 1 with a hint when `uv.lock` is stale.
- `lock-upgrade [-P PACKAGE ...]`: `uv lock --upgrade`, or `--upgrade-package` per `-P`. Prints a reminder that the
  `uv-export` and `sync-with-uv` hooks refresh `requirements.txt` and hook versions on the next commit.

### `status`

A fast read-only subset (python, uv, venv, hooks) built from the same `DoctorCheck`-returning functions `doctor` runs
(`check_python`, `check_uv`, `check_venv`, `check_hooks`). `doctor` gains the python/uv/venv checks too; `status` omits
the slow ones (stow simulation, render, Brewfile).

## Testing

TDD for every unit. Tests follow the existing patterns: mock `shell_command` / `_capture`, drive commands through
`run.get_commands()[name]`, parse via `run.build_parser()`. `test_real_commands_registered`,
`test_dotfiles_commands_registered`, and the `Makefile` drift guard are updated with each registry change. Final gate for
each PR: full `pytest`, `ruff check`, and `prek run --all-files` green.

## Documentation

Per PR: `run.py` module docstring, `docs/RUN_PY_REFERENCE.md`, `README.md`, `.ctx/ARCHITECTURE.md`, `.ctx/BUILD.md`,
and the regenerated `Makefile`. PR B adds `scripts/install/README.md` and `scripts/env/README.md` and updates
`scripts/README.md`.

## Risks

| Risk                                                           | Mitigation                                                                                  |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `doctor --fix` prompting breaks unattended use                 | `-y/--yes`; `bootstrap --verify` never passes `--fix`                                       |
| Large copied scripts fail this repo's stricter lint settings   | Fix in place; no blanket excludes                                                           |
| Scrubbed copies drift from the work originals                  | Scrub rules documented per directory; re-sync is a repeatable copy-and-scrub                |
| A work-only value reaches the public repo                      | Leak guard on every commit; scrub tests assert the internal markers are absent from scripts |

## Out of scope

`uv-tools-dump` and the uv-tool receipt parsing, `vscode-extensions-dump/install`, `report`, `backup`, `test-vm`, the
`test-*` variants, `bootstrap` through `uv run`, and work's `Makefile`-spacing option.
